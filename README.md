# MSLU App
Приложение для доступа студентов Московского государственного лингвистического университета.


## Основные понятия и термины

- **Успеваемость**: Данные об оценочных ведомостях, зачетах и экзаменах студента, загружаемые из личного кабинета.

- **Расписание**: занятия в сетке (лекции, семинары, лабораторные) с привязкой к дате, времени, номеру группы и преподавателю.

- **Авторизация**: Процесс аутентификации пользователя через корпоративную учетную запись МГЛУ.

- **Аудитории и корпуса**: Пространственные объекты университета, используемые в модуле навигации.

- **Уведомления**: Системные события и оповещения об изменениях в графике учебного процесса.

### Аннотация
  Приложение **MSLU App** представляет собой мобильный клиент для студентов и преподавателей Московского государственного лингвистического университета (МГЛУ). Проект предназначен для получения информации о расписании занятий, новостях университета и интеграции с внутренними сервисами вуза через API.


### Проблема

У студентов МГЛУ уже есть веб-версия личного кабинета, но она не решает задачу полноценно:

- **Нет постоянной авторизации.** Веб-сессия быстро истекает — приходится снова вводить логин/пароль вместо мгновенного доступа к расписанию перед парой.
- **Нет push-уведомлений.** Об отмене пары, переносе аудитории или новой оценке студент узнаёт, только если сам зайдёт и проверит — часто уже постфактум.

### Решение

MSLU App закрывает именно эти пробелы:

- **Запоминает пользователя** — залогинился один раз, дальше вход происходит автоматически и незаметно.
- **Push-уведомления** о ключевых событиях: замена пары, отмена, новая оценка, дедлайн ДЗ.
- **Мгновенный отклик** — расписание и оценки открываются сразу, даже без интернета, обновление происходит в фоне.

## Основные возможности

- Просмотр расписания занятий (день/неделя/месяц)
- Просмотр успеваемости (зачетной книжки и баллов)
- Просмотр профиля студента (личные данные, приказы и тд надо расписать)
- Просмотр домашнего задания с напоминаниями о дедлайнах
- Работа без интернета — данные всегда под рукой

---

### 1. Как работает авторизация клиента?

Студент входит по логину и паролю один раз. Дальше приложение само поддерживает сессию активной до 30 дней — не нужно логиниться заново при каждом открытии.

- **Один вход — постоянный доступ.** После первого входа приложение помнит пользователя и открывается сразу на главном экране.
- **Незаметное обновление сессии.** Если сессия истекает, приложение обновляет её в фоне — студент не видит ни экрана логина, ни ошибок, ни задержек.
- **Безопасный логин по желанию.** Опционально можно подключить двухфакторную аутентификацию (код из приложения-аутентификатора) для дополнительной защиты аккаунта.
- **Автоматический выход при компрометации.** Если кто-то попытается использовать старую, уже недействительную сессию — она отзывается, и потребуется повторный вход.

### 2. Возможности домашнего экрана

Домашний экран — это то, что студент видит первым: сводка дня в одном месте.

- **Текущая и ближайшая пара** — предмет, тип занятия, преподаватель, аудитория, крупно и заметно.
- **Расписание на сегодня** — оставшиеся пары списком, с временем и локацией.
- **Неделя (четная/нечетная)** — понятно, какая сейчас учебная неделя, с возможностью принудительно обновить данные.
- **Дата, день недели и корпус**, где проходят занятия.
- **Домашние задания** — счётчик несданных ДЗ с индикатором срочности по дедлайну.
- **Уведомления** — колокольчик с количеством непрочитанных событий (замены, отмены, новые оценки).
- **Быстрый переход** в расписание, профиль и успеваемость одним тапом.
- **Работает офлайн** — все данные показываются мгновенно из локального кеша, даже без сети.

### 3. Возможности профиля студента

- Личные данные: ФИО, фото, группа, курс, специальность.
- Просмотр и редактирование контактных данных.
- Настройки уведомлений — какие события присылать push-уведомлением, а какие нет.
- Управление безопасностью аккаунта: смена пароля.
- Выход из аккаунта на текущем устройстве.
- Информация об учебных группах.

### 4. Возможности расписания занятий

- Просмотр расписания по дням, неделям и месяцам.
- Переключение между учебными периодами (четность/нечетность, семестр).
- просмотр Карточка занятия: предмет, тип (лекция/семинар/практика), время, аудитория, корпус, преподаватель, ссылка на дистанционное занятие.
- Визуальное выделение изменений — перенос/замена пары, замены аудитории или преподавателя видны сразу.
- Работает офлайн — расписание доступно даже без интернета, обновляется автоматически при подключении к сети.
- Быстрый переход к деталям пары (если добавлены материалы или дополнительная информация).

### 5. Возможности успеваемости (уточняем что это во введении в терминах)

- Оценки по всем предметам за текущий семестр.
- История оценок по каждому предмету в хронологическом порядке за два семестра.
- Уведомление о появлении новой оценки.
- Доступно офлайн — последние данные всегда под рукой, даже без сети.

| :--- | :--- | :--- |
| **Время отклика (Offline-First)** | < 100 мс | Отрисовка интерфейса и данных из локальной БД (SQLite / Realm / MMKV) до отправки запроса в сеть |
| **Доставка Push-уведомлений** | < 5 секунд | Использование брокеров сообщений и пуш-сервисов (FCM / APNs) при событиях бэкенда |
| **Время холодной загрузки** | < 1.5 секунды | Оптимизация инициализации зависимостей и ленивая загрузка тяжелонагруженных модулей |
| **Доступность кэшированных данных** | 100% | Хранение полной структуры расписания текущего семестра и профиля на устройстве пользователя |
| **Отказоустойчивость API** | Graceful Degradation | При недоступности серверов МГЛУ приложение отображает актуальный срез кэша с плашкой времени последней синхронизации |

### Анализ функций и логика работы

#### 1. Алгоритм времени отклика и работы с кэшем (Offline-First)

Приложение использует паттерн **Stale-While-Revalidate** для минимизации задержки отклика интерфейса ($<100\text{ мс}$).

##### Данные, используемые для расчёта и отображения:
1. **Локальный кэш (SQLite / MMKV / Realm):** Хранит полную копию расписания, профиля, списка ДЗ, заметок и справок.
2. **Метка времени ($T_{\text{sync}}$):** Unix timestamp последнего успешного ответа от сервера для каждого конкретного модуля.
3. **Хеш состояния ($H_{\text{state}}$):** MD5/SHA256 хеш списка сущностей для быстрых проверок на изменения.

##### Алгоритм обновления и логика отображения:
1. **Пользователь открывает экран** $\rightarrow$ UI мгновенно считывает данные из локального кэша ($T < 50\text{ мс}$) и отображает их пользователю.
2. **Параллельный фоновый запрос** $\rightarrow$ Приложение отправляет на бэкенд лёгкий запрос заголовок/хеш с параметром `If-None-Match` или `last_sync_timestamp`.
3. **Обработка ответа бэкенда:**
   - **Код 304 (Not Modified):** Данные не изменились. Кэш актуален, статус обновляется без перерисовки списка.
   - **Код 200 (OK):** Бэкенд возвращает только дельту (изменившиеся записи) или обновлённый JSON. Приложение атомарно обновляет локальную БД, и UI плавно реактивно перерисовывается.
   - **Ошибка сети / Сервер недоступен:** UI показывает сохранённый кэш с ненавязчивым индикатором: *"Данные от [Дата/Время]"*.

---

#### 2. Сервис заметок для ДЗ и материалов

- **Привязка заметок:** Заметка привязывается к уникальному ID домашнего задания (`hw_id`) или конкретной пары (`lesson_id`).
- **Структура заметки:** Текст заметки, статус выполнения (В процессе / Готово), прикреплённые ссылки/файлы и общая текстовая заметка к заданию.
- **Синхронизация:** Заметки сохраняются локально сразу при вводе и отправляются на бэкенд в фоновом режиме через очередь синхронизации (Sync Queue).
- **Управление уведомлениями заметок:** В настройках профиля доступен отдельный переключатель *"Уведомления о заметках и напоминаниях ДЗ"*. При его отключении сервер исключает push-триггеры для дедлайнов заметок пользователя.

---

#### 3. Просмотр материалов, справок и приказов

- **Учебные материалы:** Просмотр методических пособий, ссылок на диски и файлов, прикреплённых преподавателем к дисциплине.
- **Реестр приказов:** Отображение официальных приказов вуза (о зачислении, переводе, назначении стипендии, пересдачах) с возможностью фильтрации по дате.
- **Заказ и просмотр справок:** Отображение текущего статуса заказанных справок (например, справки об обучении в ВУЗе) и скачивание их электронных версий (PDF).
